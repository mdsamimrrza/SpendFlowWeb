## Web detail upgrades (deliberate divergence — recorded per AGENTS.md)

The web client intentionally renders MORE detail than the APK from the same
shared backend (no schema changes; every field below already exists in the DB
and/or the mobile row payload). These are scope decisions, not drift:

- **Slide-over record sheets** (`components/ui/SlideOver` +
  `ExpenseDetailSheet`): full un-truncated description/notes, exact FX math
  (`1 CUR = x.xxxxxx USD` snapshot, USD base amount, basis currency), entry
  time, linked account, recurring-rule provenance, created/updated stamps,
  record ref — none of which fits the phone's centered modal.
- **History filter register**: all filters mobile keeps behind floating
  popovers (plus amount min/max + account, which mobile's service supports
  but never exposed) live in an inline toolbar, with query-param deep links
  (`/history?category=…&from=…`) that Analytics/P&L/Account rows drill into.
- **Ledger depth**: per-row Account/Time columns + notes/receipt/recurring
  indicators; Analytics drills with counts; P&L budget-per-month column and
  settings change log (append-only trail surfaced, not just written).
- **Entry form (SF-01, 2026-09-13)** — beyond display upgrades, two deliberate
  write-surface divergences, all within the existing schema: the DETAILS
  **notes** field (mobile has the column but never exposed an input) and the
  **snapshot-date lock** on the hero FX line (default follows the transaction
